# Архітектурна специфікація бібліотеки Jemini

## 1. Загальна концепція та мета
**Jemini** — це незалежна, модульна Python-бібліотека з відкритим кодом (GitHub репозиторій `TMishkaw/Jermina`), призначена для повного циклу автоматизованого створення контенту, публікації, аналізу ефективності та саморозвитку контент-каналів на базі Gemini API.

---

## 2. Ключові підсистеми

### Підсистема 1: Ротатор ключів та облік квот (Key Rotator & Quota Manager)
- **Структура даних у PostgreSQL (`api_keys`)**:
  - `key_string`: секретний ключ API.
  - `engine`: провайдер моделі (`gemini`, заділ на `openai` тощо).
  - `key_type`: пріоритет безкоштовних лімітів (`free`), платні (`paid`) як резерв для важких задач.
  - `models_mapping`: підтримувані моделі та їхні специфічні квоти.
  - `status`: поточний стан (`active`, `rate_limited`, `exhausted`, `banned`).
  - `cooldown_until`: часова мітка блокування для пари `[ключ + модель]` після отримання 429.
- **Model Routing**:
  - *Диференціація за складністю*: автоматичний вибір моделі (`ROUTINE` &rarr; `gemini-2.5-flash`, `COMPLEX` &rarr; `gemini-2.5-pro`, `LIVE_STREAM` &rarr; `gemini-3.8-live`).
  - *Ізоляція лімітів на рівні моделей*: вичерпання ліміту важкої моделі не блокує легку модель на тому самому ключі.
  - *Спільні ключі між проєктами*: єдиний облік запитів і блокувань.
- **Обробка помилок 429 та Hot Standby**:
  - Зчитування `retry_after` і миттєве виключення пари `[ключ + модель]`.
  - Безшовна міграція (seamless switch) активних сесій без обриву стрімів чи завдань.

### Підсистема 2: Універсальний двигун Gemini Live API
Єдина мультимодальна система для 3 ключових сценаріїв:
1. **Сценарій А: Мультимодальний відео- та аудіоаналіз (Video Intelligence & Evaluation)**
   - Потокова відправка фреймів та аудіо згенерованого відео через Live API.
   - Оцінка контенту за жорстким системним промтом (хук, динаміка, акторський стандарт).
   - Результат: виключно структурований JSON-звіт (`VideoReviewReport`) для системи самонавчання.
2. **Сценарій Б: Парсинг живих ефірів та взаємодія (Live Stream Vision & Parsing)**
   - Візуальний парсер прямих трансляцій (TikTok / YouTube).
   - Розпізнавання безпосередньо з екрана подарунків, лайків, коментарів, дій глядачів та подій у чаті.
   - Перспективний заділ: автоматичні інтерактивні сценарії та «батли» між власними лайв-каналами.
3. **Сценарій В: Синтез мовлення та озвучування (AI Voice TTS)**
   - Подача реплік у Live API із системними інструкціями щодо тональності, емоцій та стилю подачі.
   - Дотримання **Golden Acting Standard** (голоси: `Zephyr`, `Aoede`, `Fenrir`, `Kore`, природний сміх, vocal fry, шепіт).

## 3. Global Quality Gates & Engineering Standards

1. **Сувора типізація та стандарти коду (Strict Typing & Code Style)**:
   - Повна статична типізація.
   - Автоматизована перевірка та форматування через `ruff`.
2. **Покриття тестами та гарантія регресії (Testing Pyramid)**:
   - **Юніт-тести**: обов'язкове покриття всіх модулів через `pytest`.
   - **Інтеграційні тести**: зв'язка Ротатора, PostgreSQL та Live API.
   - **Fault Injection (Емуляція помилок)**: обов'язкове тестування масових помилок 429, обривів мережі та вичерпання пулу ключів.
3. **Безпека та ізоляція конфігурацій (Security & Config Hygiene)**:
   - Жодних хардкод-секретів: конфігурація через змінні середовища (`.env`) та Pydantic Settings.
   - Пісочниця для агентів саморозвитку перед створенням Pull Request.
4. **Надійність та обробка винятків (Resilience & Error Handling)**:
   - **Graceful Degradation**: збій другорядних плагінів не зупиняє основний конвеєр генерації та публікації.
   - **Структуроване логування (JSON)** безпосередньо в PostgreSQL.
   - **Векторна пам'ять (pgvector)** для накопичення досвіду експериментів, помилок парсингу та патернів сценаріїв.
