# Архітектура та налаштування кастомних субагентів (Custom Subagents)

> **Субагенти (Subagents)** в Antigravity дозволяють делегувати паралельні збірки, багатофайлову кодогенерацію, дослідження кодової бази та аудити незалежним фоновим агентам, зберігаючи активний робочий потік розробника.

---

## 1. Запуск та ізоляція середовищ

Субагент запускається через інструмент `invoke_subagent`:
- **Workspace-режими**:
  - `inherit`: успадковує ту саму робочу директорію, що й батьківський агент.
  - `branch`: створює ізольоване **Git worktree** для паралельної роботи над окремою гілкою без конфліктів у файлах.
  - `share`: спільне сховище без дублювання дискового простору.
- **Ізоляція контексту**: субагент стартує з чистим контекстним вікном обраної моделі (`inherit`, `flash`, `pro`), що запобігає засміченню пам'яті.
- **Глибина вкладеності**: ліміт до **10 рівнів** вкладеності для захисту від безкінечної рекурсії.

---

## 2. Локації виявлення кастомних агентів

Antigravity автоматично сканує та завантажує агенти у форматі `.md` з наступних директорій:

| Рівень доступу | Шлях до файлу | Область дії (Scope) |
| :--- | :--- | :--- |
| **Workspace / Проєкт** | `.agents/agents/<name>.md` або `.agents/agents/<name>/agent.md` | Тільки активний репозиторій |
| **Global / Система** | `~/.gemini/config/agents/<name>.md` | Всі проєкти на комп'ютері |
| **Плагіни** | `plugins/<plugin_name>/agents/` | У складі підключеного плагіна |

---

## 3. Специфікація конфігурації (YAML Frontmatter)

На початку файлу агента обов'язково розміщується YAML frontmatter:

```yaml
---
name: video-evaluator
description: Спеціалізований субагент для аудиту згенерованого відео та перевірки Golden Acting Standard.
tools:
  - view_file
  - run_command
subagent: true
mainAgent: false
model: pro
commandExecutionPolicy: sandbox
mcpServers: []
skills: []
---

# System Prompt
Тут починається системна інструкція субагента...
```

### Параметри конфігурації:
- `name` *(string, обов'язковий)*: унікальний ідентифікатор агента.
- `description` *(string, обов'язковий)*: опис ролі для планера Antigravity при виборі субагента для делегування.
- `tools` *(list)*: точний список дозволених інструментів (наприклад, `view_file`, `replace_file_content`, `run_command`).
- `subagent` *(boolean)*: чи дозволено викликати агента через `invoke_subagent`.
- `mainAgent` *(boolean)*: чи доступний агент для вибору як основний у чаті.
- `model` *(string)*: `inherit`, `flash`, `pro`.
- `commandExecutionPolicy` *(string)*: `sandbox`, `auto`, `eager`, `off`.

---

## 4. Життєвий цикл та стани субагента

1. **Running (Виконується)**: активно виконує завдання, робить tool calls. Зупинка: кнопка *Stop Subagent* або клавіша `k` в CLI.
2. **Idle (Очікування)**: завершив роботу, надіслав звіт батьківському агенту і став на паузу. Зберігає всю історію; пробуджується автоматично при надходженні нового повідомлення.
3. **Killed (Знищений)**: остаточно завершений, його тимчасовий Git worktree автоматично видаляється, а транскрипт зберігається у JSONL логах.

---

## 5. Багатоагентні оркестратори

- **`/boost`**: трирівнева ієрархія глибокого мислення (`Orchestrator` &rarr; координатори `DeepCoder` / `DeepInvestigator` &rarr; воркери) для складних алгоритмічних завдань та паралельного рефакторингу.
- **`/teamwork-preview`**: автономна команда агентів для масштабних проєктів (декомпозиція майлстоунів, паралельна реалізація та незалежна верифікація).

---

## 6. Ергономіка та шорткати в CLI

- `/agents`: інтерактивна панель керування активними та завершеними агентами.
- `/tasks`: відстеження не-агентних фонових процесів (термінальні команди, тести).
- `Alt + J`: миттєва навігація ("телепорт") до наступного субагента, який очікує підтвердження дії.
- `Ctrl + K`: швидке підтвердження (Fast-path) дії агента без перемикання вікон.
