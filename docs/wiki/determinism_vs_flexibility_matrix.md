# Матриця детермінованості та гнучкості системи Jemini

Система спроєктована за принципом **«Жорсткий фундамент — гнучкі агенти»**:
Код, інфраструктура, ротація ключів та пайплайни безпеки — повністю детерміновані та захищені від випадкових помилок. Контент, стилістика, сценарні експерименти, парсинг стрімів та адаптація під канали — максимально гнучкі, керовані ШІ та системою самонавчання.

---

## 1. Рівень Ядра (Core & Engine) — Строго детерміновано

Ядро бібліотеки та базові інфраструктурні компоненти не «вигадують» логіку на ходу, а працюють за суворими математичними та програмними правилами:

- **Пайплайн Git Flow та розробки:**
  - Перенесення коду виключно за маршрутом `dev` $\rightarrow$ `Antigravity` тестування $\rightarrow$ `release`/`main`.
  - Заборона агентам редагувати код напряму в обхід GitHub Issues та Pull Requests.
- **Ротатор ключів та обробка 429:**
  - Логіка перемикання ключів, облік квот, розрахунок таймерів `cooldown_until`.
  - Пріоритет Free-Tier над Paid, ізоляція кулдаунів для пари `[ключ + модель]` та миттєвий Hot Standby.
- **Структура БД (PostgreSQL + pgvector):**
  - Незмінні типізовані схеми таблиць, міграції, стандарти векторів `Vector(768)`.
- **Стандарти коду:**
  - Сувора статична типізація (Pydantic v2, MyPy), лінтери (`ruff`) та 100% проходження тестів (`pytest`).

## 2. Рівень Мозку та Контексту (AI & Context Layers) — Гібридний

Поєднує стабільні інваріантні системні правила та динамічні дані каналу.

### Що детерміновано (Каркас):
- **Ієрархія завантаження контексту:** Порядок склеювання шарів є незмінним:
  $$\text{Базовий шар (Core)} \rightarrow \text{Доменний шар (Domain)} \rightarrow \text{Контекстний шар каналу (Channel)}$$
  Агент завжди завантажує контекст каскадно, а не хаотично.
- **Формат маніфестів:** Структура конфігураційних файлів каналу (YAML/JSON) строго типізована через Pydantic-моделі (`ChannelProfile`).

### Що гнучке (Зміст):
- **Промпти та персоналізація каналу:** Стилістика, тональність, теми та обмеження конкретного каналу/проєкту.
- **Довготривала пам'ять (pgvector):** Накопичення досвіду експериментів, успішних патернів сценаріїв та аналітики помилок.

## 3. Рівень Роботи з Gemini Live API (Multimodal Streams) — Адаптивно-гнучкий з жорсткими тригерами

Потокові задачі взаємодіють із реальним світом (відео, прямі трансляції, аудіо).

### Що детерміновано:
- **Типи обробки запитів:** Чіткий розподіл сценаріїв:
  - *Сценарій А:* аналіз відео для тексту-рецензії та аудиту перших 3 секунд (хук).
  - *Сценарій Б:* візуальний парсинг ефірів (TikTok/YouTube) на події (подарунки, коментарі, дії).
  - *Сценарій В:* генерація озвучки TTS за еталоном Golden Acting Standard (24kHz 16-bit PCM).
- **Фолбеки та м'яка деградація (Graceful Degradation):** При збої зв'язку або 429 система не падає, а перемикається на резервний ключ або стає в чергу.

### Що гнучке:
- **Аналіз ефірів та реакцій:** Модель у реальному часі інтерпретує візуальний ряд, адаптуючись до непередбачуваної поведінки аудиторії чи подій у кадрі.

## 4. Рівень Експериментів та Саморозвитку (Evolution & Self-Evolution) — Максимально гнучкий під контролем

Модуль росту та навчання системи без втручання людини.

### Що детерміновано:
- **Межі експериментів:** Базова тематика каналу є «якірною» (незмінною). Агент не має права самовільно змінювати фундаментальну нішу каналу.
- **Критерії оцінки успіху:** Чіткі метрики (перегляди, утримання аудиторії, залученість, CTR), за якими алгоритм приймає рішення залишити чи відкинути формат.

### Що гнучке:
- **Генерація гіпотез і варіантів:** Створення нових стилів подачі, елементів динамічного монтажу, сценарних ходів.
- **Формування запитів на доопрацювання (GitHub Issues):** Автономне виявлення нестачі інструментів (наприклад, потреба нового плагіна чи ефекту) із генерацією ТЗ для розробки.
